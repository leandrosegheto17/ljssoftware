Smoke-test — Header/Nav (T2.1) + Menu mobile (T2.2)

Instruções de validação manual (teclado, header/nav): pressione Tab a partir do topo da página — o primeiro elemento focado deve ser o skip link "Pular para o conteúdo" (oculto até então, visível ao focar). Continue pressionando Tab para percorrer ícone/marca → hamburguer → Apps → Sobre → Contato de cada uma das 3 variantes acima, confirmando indicador de foco visível em todos.

Redimensione a janela (DevTools → 360px / 768px / 1024px) para confirmar o comportamento responsivo: abaixo de 768px, a nav some da linha do header e o botão hamburguer aparece; em 768px+ a nav horizontal completa reaparece e o hamburguer some — nenhuma largura produz rolagem horizontal.

Instruções de validação manual (menu mobile, T2.2) — redimensione para menos de 768px antes de testar: (1) clique no hamburguer — o overlay navy abre cobrindo o restante da página (o header branco permanece visível por cima), o ícone vira "X" e o `aria-label` muda para "Fechar menu"; o foco move automaticamente para o primeiro link ("Apps") dentro do overlay. (2) Pressione Tab pelos itens do overlay (Apps → Sobre → Contato), confirmando foco visível (indicador `--color-accent` sobre o fundo navy). (3) Pressione Escape — o overlay fecha e o foco retorna ao botão hamburguer. (4) Repita a abertura navegando só por teclado: com foco no hamburguer, pressione Enter e depois Space em outra rodada — ambos devem abrir/fechar o menu (comportamento nativo de `<button>`, sem handler dedicado). (5) Abra o menu, redimensione a janela para 768px+ sem fechá-lo manualmente — o overlay deve fechar sozinho (reset de `matchMedia` em `nav.js`) e o hamburguer some, dando lugar à nav horizontal. (6) Em sistema operacional/navegador com "reduzir movimento" ativado (`prefers-reduced-motion: reduce`), repita o passo (1) — o overlay deve aparecer/desaparecer instantaneamente, sem a transição de slide.

Nota sobre este smoke-test especificamente (não se aplica às páginas reais, que têm só um header cada): como as 3 variantes do header estão empilhadas na mesma página só para inspeção visual, abrir o overlay de uma variante pode deixar as barras brancas dos headers das variantes seguintes visíveis por cima do overlay escuro, dependendo do scroll — artefato do próprio smoke-test (múltiplos headers na mesma página), não do componente.

Contraste verificado (WCAG AA, ver comentários no topo e nas seções "Header / Nav (T2.1)" / "Menu mobile (T2.2)" de components.css): texto "LJS Software", nav e ícone do hamburguer sobre o fundo branco do header; texto branco do botão "Contato" sobre o fundo navy do header; links e indicador de foco dentro do overlay (fundo navy) e botão "Contato" reestilizado (fundo `--color-accent`) dentro do overlay — todas as combinações acima de 9:1, folga ampla sobre o mínimo 4.5:1 exigido (nenhum par novo foi introduzido, todos reaproveitam tokens já verificados em `tokens.css`/T2.1).
